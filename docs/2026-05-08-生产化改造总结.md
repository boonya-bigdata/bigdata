## 一、改造前项目诊断

| 维度 | 现状 | 严重度 |
|------|------|--------|
| 包结构 | `com.boonya.lab` / `com.chinasofti` / `com.etc` / 默认包混用 | 高 |

### 2.3 API 现代化

MapReduce 模块全部升级：

- `new Job(conf, "name")` → `Job.getInstance(conf)` + `job.setJobName("name")`
- 移除 `conf.set("mapred.job.tracker", ...)` (Hadoop 1.x 残留)
- 硬编码 `ioArgs` → 标准 `args` 命令行参数

### 2.4 共享配置模块

新建 `bigdata-common` 模块，统一管理所有大数据组件的连接配置：

- `HadoopConfig` — HDFS NameNode 地址、用户、安装目录
- `KafkaConfig` — Bootstrap Servers、Consumer Group、Topic
- `FlinkConfig` — 并行度、Checkpoint 间隔、HDFS 输出路径
- `HBaseConfig` — ZK Quorum、Root Dir
- `RedisConfig` — Host、Port、Password、连接池

配置文件: `application-shared.yml`

### 2.5 激活 flink-kafka-hdfs 模块

根 POM 取消注释，模块重新加入构建。

## 三、阶段二：工程化能力提升

### 3.1 CI/CD 流水线

新建 `.github/workflows/ci.yml`：

- **build-and-test**: Java 17 编译 + 单元测试 + 打包 + Artifact 上传
- **integration-test**: Docker Compose 启动基础设施 → 集成测试 → 清理

### 3.2 数据质量校验层

新建 `DataValidator<T>` — 链式数据校验框架：

```java
DataValidator<UserEvent> validator = UserEventValidator.create();
// 校验规则: userId > 0, page 非空, amount >= 0, timestamp 有效
```

脏数据通过 Flink Side Output 输出，不阻塞主流程。

### 3.3 测试框架

新建 `UserEventTest` — 6 个 JUnit 5 单元测试：

- `shouldSerializeToJson` — JSON 序列化
- `shouldDeserializeFromJson` — JSON 反序列化
- `shouldHandleNullSalt` — 空盐值处理
- `shouldGenerateSaltedKey` — 加盐 Key 生成
- `shouldSerializeToCsv` — CSV 序列化
- `shouldRejectInvalidJson` — 异常输入处理

### 3.4 监控指标

新建 `MetricsCollector` — 统一指标采集器：

| 指标名 | 说明 |
|--------|------|
| `records.in.total` | 入站记录总数 |
| `records.out.total` | 出站记录总数 |
| `records.error.total` | 错误记录总数 |
| `records.invalid.total` | 无效记录总数 |
| `records.skewed.total` | 倾斜记录总数 |

## 四、阶段三：生产级实战场景

### 4.1 端到端数据管道

新建 `ProductionPipelineJob` — 完整六阶段管道：

```
Kafka Source → 数据质量校验 → JSON 解析 → (脏数据SideOutput)
→ 数据倾斜感知聚合 → HDFS Raw Sink + Agg Sink → 监控指标输出
```

特性:
- Checkpoint 容错（可恢复）
- 脏数据不丢失（Side Output）
- 数据倾斜自动处理
- 滚动文件策略（5分钟/128MB）

### 4.2 数据倾斜优化

重写 `SkewAwareAggregator`：

| 改进项 | 改造前 | 改造后 |
|--------|--------|--------|
| 状态管理 | 本地 HashMap (内存泄漏) | Flink MapState (RocksDB 持久化) |
| 热点检测 | 不清理的 HashMap | 定时器触发后自动清理 |
| 聚合输出 | 随机 10% 输出 | 定时器每分钟全局聚合 |
| @Override | 注释掉的 | 正确的 open() 覆盖 |

### 4.3 配置增强

`FlinkConfig` 新增:

- `fromArgs(String[] args)` — 命令行参数解析，兼容非 Spring 环境
- 双命名 getter（`getBootstrapServers()` / `getKafkaBootstrapServers()`）兼容新老代码

## 六、快速启动命令

```bash
# 1. 启动基础设施
docker-compose up -d

# 2. 构建项目
mvn clean package -DskipTests

# 3. 运行生产管道
flink run -c com.boonya.bigdata.flink.kafka.hdfs.job.ProductionPipelineJob \
  bigdata-flink-kafka-hdfs/target/bigdata-flink-kafka-hdfs-1.0.0-SNAPSHOT.jar

# 4. 查看监控
# Grafana: http://localhost:3000 (admin/admin)
# Flink UI: http://localhost:8081
```
